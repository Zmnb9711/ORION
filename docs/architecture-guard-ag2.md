# ORION Architecture Guard AG-2

AG-2 adds a deterministic capability-centric architecture-history graph to the
private AG-1 SQLite database. It does not modify ORION runtime behavior and it
does not decide which historical implementation is preferable.

The graph answers a narrower question:

> Which decisions, implementations, mechanisms and field evidence belong to
> the same stable product capability even when their provider, class name or
> architecture changed?

## Taxonomy and nodes

Stable capability IDs are provider- and symbol-independent. Families cover DCS
and world state, interaction, AI/speech, radio, communication, ATC, mission
domains, and product/development concerns. Each capability may have aliases,
historical terms, code symbols, providers, related domains and parent/child
relationships.

Graph nodes are:

- `CAPABILITY`: stable behavioral identity;
- `DECISION`: exact D01-D73 Decision Register row;
- `IMPLEMENTATION`: a historically significant concrete ORION realization;
- `MECHANISM`: a reusable invariant smaller than an implementation;
- `EVIDENCE`: bounded AG-1 field-evidence identity;
- `OWNERSHIP_ASSIGNMENT`: an evidence-supported responsibility boundary.

Implementation `runtime_status`, `historical_status`, field/probe evidence and
abandonment reason are separate fields. Consequently, `FIELD_PROVEN` does not
mean current preference, `DISCONNECTED` does not mean historically missing,
and `EXPLICITLY_REMOVED` does not make a mechanism reusable by default.

## Relationships

AG-2 uses typed edges including `IMPLEMENTS`, `USES`, `SUPERSEDES`, `REJECTS`,
`DEPENDS_ON`, `REPLACED_BY`, `REUSES_MECHANISM`, `RELATES_TO`, `APPLIES_TO`,
`PARENT_OF`, and `FIELD_PROVEN_BY`.

Every non-taxonomy edge stores confidence and exact AG-1 source item IDs and
pointers. Taxonomy-only edges are explicitly marked `DERIVED_TAXONOMY`; they
are never represented as direct historical evidence.

The graph is a curated deterministic seed plus exact import of structured
D01-D73 rows. It is not generated by an LLM. Seed content and all resolved L0
content hashes participate in the graph input signature. An unchanged rebuild
is skipped; a changed seed or primary source triggers a transactional rebuild.

## Provenance and chronology

`graph_provenance` links every decision, implementation, mechanism and evidence
node to exact AG-1 `source_items`. It retains the original archive/Git/Evidence/
document pointer and the context item set used for the curated mapping.

Conversation-dependent decisions continue to rely on AG-1 neighbor/thread
retrieval. AG-2 does not copy private conversations into Git and does not infer
approval from an isolated preview.

## Ownership

The initial ownership register covers fact authority, semantic interpretation,
reasoning, tool permission, informational wording, protected operational
wording, phraseology, STT, TTS, voice identity, radio transport, physical PTT,
EOU, persistent state, and lifecycle. Ambiguous or disconnected ownership is
recorded as such instead of being promoted to current fact.

## CLI

```powershell
python -m tools.orion_arch_guard graph-build
python -m tools.orion_arch_guard capability AIRCRAFT_IDENTITY
python -m tools.orion_arch_guard related --capability "natural response"
python -m tools.orion_arch_guard history --capability PTT
python -m tools.orion_arch_guard explain --implementation CURRENT_AIRCRAFT_IDENTITY_QUERY
```

Capability aliases use deterministic normalized matching. Query output contains
decisions, implementations, mechanisms, evidence, ownership, relationships and
exact source pointers. `architecture_gate_result` is always null in AG-2.

## Mandatory recovered lineages

The seed deliberately preserves, without ranking:

- Stage 6A FlightContext/persistent Yandex Realtime and the current aircraft
  identity/Qwen/Core-fact-binding route under their overlapping capabilities;
- packet-gap EOU, UDP7082 true-to-false, candidate buffering and cadence-aware
  liveness;
- superseded hard language modes, follow-user input language and Communication
  Profile infrastructure;
- explicitly removed Whisper and current SpeechKit v3 External-EOU STT;
- Pilot Phraseology as `TEST_CORPUS_ONLY`, protected OSU wording and profile
  infrastructure;
- pure takeoff MODEL C, persistent ATC session and `ATC_STATUS_QUERY`.

## Privacy and limitations

The graph stores only durable non-sensitive metadata in source code and private
derived graph rows in local SQLite. It stores no raw chat body, credential,
Authorization header or audio. FTS, embeddings and vector search remain absent.

AG-2 does not implement Previous Best scoring, recommendations, automatic
supersession, or `PASS/BLOCK/USER_DECISION_REQUIRED`. Those belong to:

`AG-3 — HISTORICAL DECISION CHECK + PREVIOUS BEST SOLUTION GATE`.
